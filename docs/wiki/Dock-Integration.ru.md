# Интеграция с Dock

## Этап A — Один значок Dock (реализовано в версии 0.1)

Пользователь добавляет само приложение DockFolders в Dock. Нажатие показывает обычный обозреватель папок. Приложение реализует `applicationShouldHandleReopen`, чтобы восстановить или вывести окно на передний план через публичные API жизненного цикла приложения. Приложение не добавляет представления в системный Dock, не исправляет его и не изменяет его. Ручная проверка повторной активации из Dock ещё не проведена.

## Закрепление в Dock контролирует пользователь

DockFolders создаёт приложения-ярлыки, но не должно автоматически добавлять или удалять элементы Dock. macOS описывает добавление открытого приложения через меню Dock (**Options → Keep in Dock**) или перетаскиванием приложения в Dock; для каждого ярлыка используйте этот пользовательский способ. См. [поддержку Apple: использование Dock на Mac](https://support.apple.com/en-gb/guide/mac-help/mh35859/27/mac/27).

`NSDockTile` в AppKit позволяет менять оформление/значок уведомления плитки существующего приложения или окна. Это не публичный API для регистрации произвольной папки в Dock или скрытого закрепления приложения. Вывод следует из документированной области `NSDockTile` и пользовательского процесса Apple. Не редактируйте настройки Dock, не вызывайте закрытые API и не автоматизируйте Dock для обхода этого действия.

Создавайте стабильный ярлык для папки в `/Applications/DockFolders`, показывайте его расположение и краткую инструкцию ручного закрепления. При переименовании папки идентификатор ярлыка сохраняется, а отображаемое имя обновляется. При удалении папки можно удалить её ярлык из хранилища DockFolders; macOS может оставить устаревший элемент Dock, который пользователь удалит самостоятельно. Popup раскрывается от нажатого значка Dock и сворачивается обратно к нему при закрытии; при включённом «Уменьшении движения» переход отключён.

## Этап B — Отдельный ярлык для каждой папки (реализовано)

DockFolders создаёт приложение-ярлык для каждой папки в `/Applications/DockFolders`, используя название папки; для одинаковых названий добавляется номер. При переименовании папки меняется имя ярлыка, а UUID-ссылка сохраняется. При запуске старые ярлыки из `~/Applications/DockFolders` переносятся в новое расположение. Каждый ярлык отправляет стабильный UUID через пользовательский URL `dockfolders://folder/<UUID>`. URL проверяется до перехода к папке. При открытии popup место курсора определяет дисплей и положение значка Dock, на который нажали. `NSScreen.visibleFrame` определяет зарезервированный край Dock — снизу, слева или справа; если край не зарезервирован, ближайший к точке нажатия край используется как запасной вариант. Панель размещается внутрь экрана и ограничивается его границами. По документации Apple, `visibleFrame` учитывает текущие системные параметры и может быть меньше полного экрана даже при автоскрытии Dock ([`NSScreen.visibleFrame`](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe)). Ярлыки создаёт и обслуживает DockFolders; закрепление в Dock остаётся отдельным действием пользователя.

Каждый ярлык объявляет свой значок через `CFBundleIconFile` и содержит многослойный по разрешению ресурс `.icns`, созданный из макета 1024 × 1024 px. Благодаря этому macOS отображает его как обычный значок приложения и применяет стандартное оформление Dock. Приложение не может задать размер отдельной плитки Dock: размер и увеличение при наведении настраиваются в разделе «Рабочий стол и Dock» macOS ([поддержка Apple: настройки рабочего стола и Dock](https://support.apple.com/en-ie/guide/mac-help/mchlp1119/27/mac/27)).

URL папки обрабатывает делегат приложения напрямую через общее хранилище. Автоматического главного `WindowGroup` больше нет: окно обозревателя AppKit создаётся только при обычном запуске (`NSApplication.launchIsDefaultUserInfoKey`), явном повторном открытии или показе ошибки. Запуск служб не зависит от появления обозревателя. Регрессионные тесты проверяют запуск по URL без обозревателя, обычный запуск и повторное открытие, а также ошибку отсутствующей папки. Визуальная проверка нового пути холодного запуска ещё требуется.

Старая ошибка не заменяет popup корректной папки главным окном: сообщение показывается в popup. При запуске миграция выполняется только для старых ярлыков, которые нужно перенести или переименовать. Удаление папки сначала сохраняет изменение данных и лишь затем удаляет ярлык; при ошибке записи папка и ярлык остаются на месте.

### Настройка пользователем

1. Создайте ярлык папки в DockFolders.
2. В Finder откройте `/Applications/DockFolders` и один раз запустите созданное приложение.
3. В Dock нажмите Control-click/правой кнопкой по его значку и выберите **Options → Keep in Dock**.
4. Повторите для каждой папки, которую нужно закрепить.

DockFolders не должен записывать файлы настроек Dock, вызывать закрытые API или автоматизировать эти действия. Apple описывает процесс в [руководстве по Dock](https://support.apple.com/en-gb/guide/mac-help/mh35859/27/mac/27). `NSDockTile` настраивает плитку существующего приложения/окна, но не регистрирует и не закрепляет новые элементы Dock.

### Что ещё проверить

Маршрутизация ярлыков и холодный запуск проверены. Модульные тесты проверяют геометрию для Dock снизу/слева/справа, запасное позиционирование по курсору и привязку к дисплею. Фактическое отображение popup на нескольких физических дисплеях и варианты автоскрытия Dock, очистка устаревшего значка после удаления папки, подпись/нотариальное заверение, sandbox и распространение требуют ручной проверки.

## Этап C — Открытие наведением (реализовано; проверено частично)

Дополнительная настройка предлагает режимы «По нажатию», «При наведении» и «По нажатию и наведению»; по умолчанию остаётся нажатие, которое работает без разрешения Accessibility. Режим наведения слушает глобальные/локальные события движения мыши и проверяет элемент Dock публичным `AXUIElementCopyElementAtPosition`; сопоставляются только bundle ID созданных ярлыков и UUID папок. По умолчанию панель открывается через 180 мс, остаётся открытой при переходе курсора на неё и закрывается через 250 мс; обе задержки настраиваются. При переходе между папками панель переиспользуется. Escape и закрытие после запуска приложения сохраняются. Если установить системные мониторы событий нельзя, адаптивный резервный опрос работает редко в покое и чаще только рядом с Dock. В настройках объясняется запрос разрешения «Универсальный доступ»; запись экрана и мониторинг ввода не запрашиваются. На macOS 27 закреплённый `/Applications/DockFolders/Code.app` проверен сквозным тестом: наведение открывает нужный popup, переход курсора удерживает его открытым, уход закрывает. Переключение соседних папок, работа без разрешения и другие конфигурации дисплеев/Dock ещё не проверены.

Используются документированные API Apple: [`AXUIElementCopyElementAtPosition`](https://developer.apple.com/documentation/applicationservices/1462077-axuielementcopyelementatposition), [`AXUIElementCopyAttributeValue`](https://developer.apple.com/documentation/applicationservices/1459076-axuielementcopyattributevalue), [`AXIsProcessTrustedWithOptions`](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions), [`NSEvent.addGlobalMonitorForEvents`](https://developer.apple.com/documentation/appkit/nsevent/addglobalmonitorforevents%28matching%3Ahandler%3A%29), [`NSEvent.addLocalMonitorForEvents`](https://developer.apple.com/documentation/appkit/nsevent/addlocalmonitorforevents%28matching%3Ahandler%3A%29), `NSPanel` и `NSWorkspace`. Перевод координат привязан к AppKit-рамке главного дисплея; конфигурации нескольких дисплеев на этом компьютере не проверены.
